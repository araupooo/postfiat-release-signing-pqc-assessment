# Post-Quantum Release-Signing Assessment for PFTL

Measured signing costs for a hybrid Ed25519 + ML-DSA-65 release scheme
against SLH-DSA, with negative tests, a key-rotation drill, and a mapping
to the release and signing code in postfiatd (pinned commit
`0085a1ff885d6a446369cf73a4430f75af22be55`).

## Headline finding

The hybrid scheme wins on every measured axis on this host. Hybrid
verification costs 190.366 us (median) against 710.776 us for
SLH-DSA-SHA2-128s (liboqs) — about 3.73x faster — and a hybrid
signature is 3,373 bytes against 7,856 bytes for SLH-DSA-128s and
17,088 bytes for SLH-DSA-128f. Signing is the starkest gap: hybrid
signing costs 139.669 us while SLH-DSA-128s signing costs 692,670.570 us
(liboqs), about 4,959.4x more, because the small-signature SLH-DSA
parameter sets trade signing time for size. (Exact medians are in
`results/summary.txt`; they vary run to run.)

Recommendation: sign releases with hybrid Ed25519 + ML-DSA-65 now, keep
SLH-DSA-128s as the hash-based fallback in case lattice schemes fail.
See `release_signing_assessment.md` for the design, phased costs,
rollback protection and key-compromise response.

## What this pack contains

- `harness/sign_release.c` — liboqs 0.16.0 + OpenSSL 3.0.13 driver:
  hybrid signing, per-scheme timings, 12 negative tests, 5-step
  rotation drill. Keys are ephemeral test-only keys, generated fresh
  on every run and never written to disk.
- `harness/sign_pqclean.c` — PQClean "clean" reference driver, one
  binary per parameter set (ML-DSA-65, SLH-DSA SHA2/SHAKE 128s/128f).
- `harness/build_signing.sh`, `harness/run_signing.sh` — build / run.
- `results/signing_liboqs.json`, `results/signing_pqclean_*.json` —
  vendored raw results; `results/raw_sign_*.log` — unedited raw logs.
- `results/timing_table.*`, `results/size_table.*`,
  `results/cost_model.*`, `results/summary.txt` — derived outputs
  (regenerated by `build_derived.py`).
- `docs/index.html` — rendered results page (GitHub Pages, /docs).
- `call_sites.md` — measurement-to-call-site mapping in postfiatd.
- `release_signing_assessment.md` — the assessment itself.
- `claim_evidence_index.md` — measured vs source-derived claims.
- `sources.md`, `sources/NIST.FIPS.204.pdf`,
  `sources/NIST.FIPS.205.pdf` — primary sources.

## Reproduction

```sh
bash run_all.sh
```

Regenerates every derived output offline from the vendored results
JSON, rebuilds the rendered page, and verifies digests. Expected:
exit 0, byte-identical outputs. See `REPRODUCTION.md`.

## Finding: postfiatd has no release-artifact signing

`docs/RELEASE.md` in the pinned tree describes a version-string +
Docker-tag + GitHub Release process with no artifact signatures or
checksums. The closest real code is the validator manifest system
(`src/xrpld/app/misc/Manifest.h:66-77`, `src/xrpld/app/misc/detail/Manifest.cpp:196`)
and transaction/validation signing
(`src/libxrpl/protocol/SecretKey.cpp:230-276`,
`src/libxrpl/protocol/STValidation.cpp:131-141`). See `call_sites.md`.
